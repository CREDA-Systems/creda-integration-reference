# CREDA Reference Architecture

## Purpose

This document describes the public integration architecture for the CREDA® Integration Reference repository.

It is intentionally high-level and non-normative.

It does not disclose the complete CREDA runtime, proprietary orchestration logic, internal services, protected implementation methods, or patent-sensitive technical details.

## Architectural Principle

CREDA® separates the system requesting governance evaluation from the infrastructure that ultimately consumes, records, or executes the resulting governance decision.

The public reference architecture exposes the integration boundary without exposing the proprietary machinery inside the CREDA implementation layer.

## Requesting System

A requesting system may be:

* an application;
* an AI agent;
* an enterprise workflow;
* a smart-contract integration;
* a credential or identity system;
* an API client; or
* another system proposing an action capable of creating consequence.

The requesting system submits a governance request using an implementation-defined integration interface.

## Governance Request

A public governance request may identify:

* the request;
* the proposed action;
* the subject or actor;
* the target resource;
* relevant governance context;
* applicable authority-state references;
* requested scope; and
* implementation-specific metadata.

The public schema published in this repository is intentionally limited.

It does not define the complete set of information required by a production CREDA implementation.

## CREDA® Implementation Boundary

The CREDA implementation boundary represents the proprietary processing layer responsible for evaluating the submitted request.

Public documentation may describe inputs and outputs of this boundary without disclosing internal methods.

Internal behavior may include separately maintained logic relating to governance-state processing, policy evaluation, authority resolution, integrity, provenance, replay, orchestration, and other implementation functions.

Those mechanisms are outside the scope of this repository unless expressly published.

## Governance Response

A governance response provides a machine-readable result that a downstream system can consume.

A public reference response may contain:

* the request identifier;
* the result or disposition;
* a decision or artifact reference;
* relevant authority-state references;
* evaluation-context references;
* timestamps;
* integrity or provenance references; and
* implementation-specific metadata.

The public response schema is an integration interface, not a complete representation of CREDA internal state.

## Infrastructure Adapter

An infrastructure adapter translates or transports a CREDA governance result into a form appropriate for an external environment.

Potential targets include:

* distributed ledgers;
* blockchain networks;
* smart contracts;
* enterprise applications;
* workflow systems;
* APIs;
* identity infrastructure; and
* legacy platforms.

The adapter should not silently reinterpret or redefine the governance result generated by the CREDA implementation.

## Relationship to VTI Foundation Inc.

CREDA Systems may implement against standards, interfaces, or governance concepts developed or stewarded by VTI Foundation Inc.

The public CREDA integration architecture is distinct from the standards and certification functions of VTI Foundation Inc.

This repository does not define VTI conformance, certification, verification, or conformity-assessment requirements.

## Public / Private Boundary

This repository may expose:

* interface definitions;
* schemas;
* examples;
* adapter patterns;
* implementation-neutral documentation; and
* public reference integration code where appropriate.

It does not, by default, expose:

* proprietary orchestration logic;
* protected authority-resolution methods;
* canonicalization mechanisms;
* replay or reconstruction internals;
* integrity-value generation methods;
* internal policy-resolution behavior;
* production security architecture;
* certification logic; or
* unpublished patent-sensitive implementation details.
